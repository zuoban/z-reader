Interpretation:
- Broad and deep searches seek the sorted index and stop at one page/lookahead.
- Selective queries use durable posting counts, the rarest posting list and one
  exact text comparison. Counts avoid re-counting postings on every request.
- Single-rune search already used sorted early stop; its time remains similar.
- First-page list timings remain similar.
- Progress changes only recent_read keys in the user and category indexes and
  decodes/verifies the book once. Synchronous commit latency remains dominant;
  these results do not establish a progress latency improvement. Compare
  allocation/byte reductions as well as elapsed time.
- Category search and deep category pages are new functionality. No prior
  server-side category-index baseline exists. Their scenarios use 分类-03 and
  cursor benchmark-08993, returning 50 books in title order.
- Deep broad search uses cursor benchmark-08999 in title order.

Operational behavior:
- Schema migration 10 rebuilds the category sort index, gram counts, missing-hash
  backlog and legacy content membership in one transaction. A record failure
  rolls back schema version and all rebuilt indexes. It performs metadata work;
  legacy file hashing runs after startup in one worker, 16 files per batch.
- Each hash batch performs one durable transaction. Between automatic batches
  the worker yields for 100ms; it revisits failed files after one minute.
- Hash-index misses with no backlog read at most one backlog index entry. If
  legacy records remain, the upload waits for the single worker's user-specific
  pass so their duplicates are checked before acceptance. Unreadable files keep
  their durable backlog entries for retry, preserving prior per-check behavior.
- Worker shutdown is checked between files and batches; an in-flight file hash
  finishes before graceful shutdown completes.
- Existing ListBooksBySortedCursor/SearchBooks callers remain valid. An optional
  final *string filter uses nil=all, pointer-to-empty=uncategorized, other=category.
- GET /api/books and /api/books/search: category=<actual category> or
  uncategorized=true; an actual nonempty category takes precedence.
- GET /api/books/status?book_ids=id1,id2 returns {"books":[Book,...]}, at most
  500 unique requested IDs; unknown and unowned IDs are omitted.

Pagination compatibility: PATCH /api/books/categories accepts
{"from":"source","to":"destination"} or to:null/empty to remove a complete
category. Both fields are required; names are trimmed; source must be nonempty.
Response: {"updated_ids":[...],"category":"destination"}; category is omitted
when removing. It uses the user/category index and one transaction to update
all source books (including unloaded pages), search/index counts and summary.
Regression coverage includes >50 source books, a different unselected category,
user isolation, invalid input, and rollback after a stored-record error.
