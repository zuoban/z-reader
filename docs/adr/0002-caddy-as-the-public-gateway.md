# ADR-0002：使用 Caddy 作为同源公网入口

- 状态：Accepted
- 日期：2026-07-27

## 背景

自部署用户需要 HTTPS、安全响应头和同源 API，而不应在浏览器中暴露内部服务端口或维护
复杂的跨域规则。前端与后端又需要保留独立的运行时与开发体验。

## 决策

生产镜像使用 Caddy 作为唯一公网入口。它终止 TLS、添加安全响应头，并将 `/api/*`、
`/healthz` 和 `/readyz` 转发给本地 Go 服务；其余页面请求转发给本地 Next.js。
Next.js 在开发或 SSR 场景通过内部地址访问 Go API。

## 后果

- 浏览器默认访问同源地址，Cookie 会话不需要额外 CORS 配置。
- 指标端点不会经 Caddy 自动公开，必须显式启用并从内网采集。
- 单镜像运行多个进程，降低部署复杂度，但不提供前端、后端的独立横向扩展能力。
